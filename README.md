# RADAR · 공시의 작은 변화까지

React + TypeScript + Vite + Tailwind CSS로 만든 공시 변화 모니터링 인터페이스입니다. 연노랑과 차콜 테마, 자체 레이더 심벌, PC 사이드바와 모바일 하단 메뉴를 제공합니다. KB를 연상시키는 색감 요청을 반영한 독립적인 프로젝트이며 금융기관의 공식 앱이 아닙니다.

## VS Code에서 실행

Node.js 22.12 이상(현재 검증 환경: Node.js 26)이 필요합니다.

1. VS Code에서 이 저장소의 `KDA1` 폴더를 엽니다.
2. 터미널에서 아래 명령을 실행합니다.

```powershell
npm install
npm run dev
```

PowerShell에서 npm 실행 정책 오류가 나면 `npm.cmd install`, `npm.cmd run dev`를 사용하세요.

브라우저에서 **http://127.0.0.1:5173/** 을 엽니다. 개발 서버는 켜두어야 합니다. 포트 사용 중 오류가 나오면 기존 서버 터미널에서 Ctrl+C로 종료한 뒤 다시 실행하세요. 주소 뒤에 `**`를 붙이지 마세요.

이전 명령 `node server.mjs`도 Vite 개발 서버로 연결됩니다. 첫 실행에는 `npm install`이 필요합니다.

## 프로젝트 구조

```text
KDA1/
├─ public/logo.svg          # 레이더 심벌과 파비콘
├─ src/
│  ├─ components/ui.tsx     # 로고, 카드, 수치 비교, 모달, 종목 검색
│  ├─ lib/data.ts           # 타입과 가상 데이터
│  ├─ lib/store.tsx         # 공유 상태, 브라우저 저장, 이동 보호
│  ├─ screens/              # 피드, 종목, 상세, 알림, 설정
│  ├─ App.tsx               # 반응형 앱 셸과 메뉴
│  ├─ index.tsx             # React 진입점
│  └─ tailwind.css          # Tailwind v4와 테마 스타일
├─ tests/                  # 사용자 동작 중심 자동 검사
├─ design/                 # 제공된 PNG 14개 (원본 유지)
├─ index.html
├─ package.json
├─ package-lock.json
├─ tsconfig.json
├─ vite.config.ts
└─ server.mjs               # 이전 실행 명령 호환
```

Tailwind v4의 Vite 플러그인과 CSS `@theme`을 사용하므로 별도 `tailwind.config.js`, `postcss.config.js`는 필요하지 않습니다. `node_modules/`와 `dist/`는 Git에 올리지 않습니다. 저장소를 내려받으면 `npm install`로 의존성을 설치합니다.

## 구현 기능

- 변화 피드: 전체·내 종목·저장함, 공시 검색, 보고서·접수 유형 필터, 최신순·변동률순 정렬
- 정정 공시 비교 팝업: 이전·정정 문장을 좌우로 표시하고 변경 수치를 강조, 슬라이더로 비교 초점 이동
- 임의 공시 2건 비교: 피드의 `두 공시 비교`에서 서로 다른 기업·공시를 각각 선택해 원형 문안과 주요 숫자를 나란히 확인
- 홈 환율 보드: USD/KRW 최신 공개 환율, 제공 데이터의 갱신 시각·종가 여부, 7·30·90일 환율 동향 그래프와 수동 새로고침
- 관심종목: 기업명·가상 코드·업종 검색, 추가·삭제, 삭제 취소, 온보딩
- 공시 상세: 공시별로 일치하는 수치 비교, 증감 바, 신규 문서 비교 불가 안내, 요약 복사, 북마크
- AI 근거: 사실과 예시 해석 분리, 원문 예시 펼치기, 확인 체크리스트, 정정 타임라인
- 알림: 개별 읽음·모두 읽기, 안 읽은 알림 필터, 미확인 배지
- 설정: 개별 토글, 발송 방식, 방해금지 시간, 보고서·종목별 설정, 변경 표시, 저장·되돌리기, 이동 시 미저장 확인
- 예외 상태: 관심종목 없음, 이전 문서 없음, 수집 실패 등 5개 상황별 안내
- 접근성: 버튼 이름, 선택 상태, 키보드 포커스, 네이티브 대화상자, 줄어든 움직임 설정 대응

관심종목·저장한 공시·읽음 상태·체크리스트·저장한 설정은 현재 브라우저의 localStorage에 보관합니다. 기존 버전의 관심종목과 설정 키를 재사용하고 값 형식을 검사합니다. 기기 간 동기화는 없습니다.

## 데이터와 디자인 범위

공시 본문과 수치·날짜는 화면 구성과 비교 기능을 위한 예시 문안입니다. 실제 DART 원문 수집, AI 생성, OS 푸시, 서버 저장은 연결되지 않았습니다. 비교 팝업 안에서 예시 문안임을 안내하며 DART 검색 링크는 DART 홈페이지를 엽니다. 투자 판단용 서비스가 아닙니다.

USD/KRW는 CxRates 공개 환율 API를 사용합니다. 최신 공개 기준 시세를 가져오며 60초마다 다시 확인하고, 제공 API가 각 환율을 갱신한 시각과 종가 여부를 표시합니다. 동향 그래프는 일별 종가입니다. 은행 송금 환율 또는 초 단위 체결가가 아니며, API 오류 시 마지막 정상 데이터와 그 기준 시각을 유지합니다.

제공된 PNG 14개를 기능 기준으로 유지하고, 사용자 요청에 따라 연노랑 테마와 PC/모바일 UI로 재설계했습니다. Figma 원본 URL이 없어 레이어를 직접 변환한 결과는 아닙니다. 로고와 UI는 SVG/CSS/React 요소로 표시하며 전체 화면 PNG를 앱 배경으로 사용하지 않습니다.

## 폼폼 플로팅 챗봇
- 모든 페이지 오른쪽 아래 캐릭터를 누르면 앱 사용 도움말 대화창이 열립니다. 사용자 제공 `public/chatbot/pompom.jpg` 원본을 CSS로 일부 표시하며 원본은 수정하지 않았습니다.
- 관심종목, 알림 설정, 정정공시, 가상 데이터 안내와 페이지 바로가기를 제공합니다. 준비된 답변을 사용하는 데모이며 외부 AI/API 연동 및 서버 대화 전송은 없습니다.
- 페이지 이동과 접기 후에도 대화가 유지되며 새로고침하면 초기화됩니다. 최근 40개 메시지만 유지합니다. Escape 닫기, 입력 포커스 복귀, 동작 줄이기 설정을 지원합니다.
- 모바일 하단 메뉴 및 설정 저장 영역을 피하도록 배치했습니다. 원격 마우스 문제로 브라우저 육안 검증은 수행하지 않았습니다.
- 검증: npm run build 성공, npm test 22개 통과 (대화 전송·초기화·이동 후 유지·키보드 닫기 포함).

### Supabase 연결
1. `.env`에 `VITE_SUPABASE_URL`과 `VITE_SUPABASE_PUBLISHABLE_KEY`를 입력합니다. `.env`는 `.gitignore`에 제외되어 GitHub에 올라가지 않습니다.
2. 저장소의 `supabase/migrations/202610300001_user_preferences.sql` 전체를 Supabase Dashboard → SQL Editor → New query에 붙여넣고 Run을 누릅니다. 이 SQL은 사용자별 `user_preferences` 테이블과 본인 행에만 접근하는 RLS 정책을 만듭니다.
3. `.env`를 처음 만들거나 수정했다면 Vite 개발 서버를 `Ctrl+C`로 종료한 뒤 `npm run dev`로 다시 실행합니다. 배포 서비스에도 같은 두 `VITE_SUPABASE_*` 환경변수를 production/build 환경에 별도로 등록한 후 다시 배포해야 합니다.
4. 이메일 인증이 켜져 있다면 회원가입 이메일을 확인한 후 로그인합니다. 로그인 후 관심종목 추가나 알림 설정 저장으로 동기화를 확인합니다. Dashboard → Table Editor → `user_preferences`에서 계정 UUID 행과 저장된 값을 확인할 수 있습니다.

환경 오류가 표시되면 `.env`의 변수 이름에 `NEXT_PUBLIC_`가 아니라 `VITE_`를 사용했는지, 개발 서버를 재시작했는지 확인합니다.

이메일 인증을 사용하지 않고 데이터베이스에 저장하려면 로그인 화면의 **이메일 인증 없이 바로 시작** 버튼을 사용합니다. Supabase Dashboard → Authentication → Sign In / Providers → Anonymous Sign-Ins를 활성화해야 하며, 익명 사용자도 `user_preferences` RLS를 통과해 저장합니다. 익명 계정은 같은 브라우저에 연결되며, 기기 변경/브라우저 데이터 삭제 전 계정 전환 기능을 별도 구현해야 합니다.

회원가입은 이메일·비밀번호 방식을 유지하고, 전화번호는 로컬 데모 인증번호 입력 후 Supabase Auth의 사용자 메타데이터와 `user_preferences` 프로필 행에 저장합니다. 실제 SMS 인증은 발송하지 않습니다. 연락처 컬럼 추가 SQL: `supabase/migrations/202610300002_contact_fields.sql`. 기존 SQL Editor에 전체 내용을 한 번 실행하세요. 비밀번호는 Supabase Auth가 해시로 관리하며 앱 DB 테이블에 평문으로 저장하지 않습니다.
